# 클립보드 채팅 결과 전달·기본 권한 변경

2026-10-26, 검증 커밋 미기록(로컬 변경). 커밋·푸시·운영 배포 없음.

## 변경

- 이전에는 Native가 읽은 텍스트를 로컬 UI에만 표시하고 AI에는 완료 요약만 전달했음. 채팅으로 요청한 성공 결과에 이제 `result.text`를 포함함.
- NestJS는 기존 티켓·권한·실행 검증 이후 UTF-8 65,536바이트 이하의 문자열을 확인하고 AI `/agent/tool-result`에 `result: { text }`로 전달함. 빈 문자열은 실제 빈 클립보드로 전달하며 원문 누락과 구분함.
- 읽기 기본값: SAFE / ALWAYS_ALLOW. 사용자가 저장한 ASK·DENY는 유지함.
- 쓰기 기본값: CONFIRM / ASK. 기존 클립보드 교체 주의사항과 저장할 텍스트 앞부분을 표시하고 Rust 일회성 승인 후 실행함. 기존 ALWAYS_ALLOW도 쓰기의 별도 확인을 생략하지 않음.
- Native 직접 테스트 결과는 로컬 표시만 유지함. 이번 변경은 채팅 결과 전달 경로이며 음성 결과 전달 검증으로 확대하지 않음.
- 실행 추적·도구 로그에는 원문을 추가하지 않음. 다만 사용자가 요청한 채팅에서는 AI에 텍스트가 전달되고 AI 답변에 포함된 내용은 대화 이력에 저장될 수 있음.

## 검증

- 백엔드 단위·모의 테스트 13개 통과: 기본 권한, 저장된 차단, 쓰기 필수 확인, 텍스트 전달, 빈 문자열, 원문 누락·자료형·크기 거부, 실행 로그 원문 제외.
- Rust 위험도 단위 테스트 1개 통과: 읽기 SAFE / 쓰기 CONFIRM.
- Chrome 모의 API·IPC 2개 통과: 읽기 기본 승인 없이 결과 텍스트 전달, 쓰기 승인 전 미실행 및 승인 후 실행. 실제 사용자 클립보드를 읽거나 변경하지 않음.
- NestJS 빌드·데스크톱 빌드 통과. 운영 프론트 산출물의 Native 개발 패널 제외 확인. 기존 번들 크기 경고 유지.
- 과거 실제 Windows 직접 읽기 통과 기록은 유지하되, 이번 변경 후 실제 AI 응답까지 확인한 것으로 보지 않음.

## 남은 사용자 확인

후속 UI 수정: 채팅 읽기는 별도 클립보드 결과창 없이 AI 답변만 표시. 직접 Native 테스트의 결과창은 유지. Rust 승인 만료는 `NATIVE_APPROVAL_EXPIRED`로 구분하며, 승인 실패를 사용자 취소로 전달하던 처리를 수정함. 미실행 실패는 FAILED로 보고하고 AI에 만료/승인 상태 오류 사유를 전달함. 실제 취소 버튼은 기존 사용자 취소 경로 유지. Chrome 모의 API·IPC 3개, Rust 승인 테스트 3개, 백엔드 결과 전달·AI 어댑터 테스트로 확인하며 실제 사용자 대기 후 AI 응답 재확인은 별도 대기.

1. 로컬 백엔드와 개발 데스크톱을 재시작.
2. 읽기에 저장된 ASK 설정이 있다면 설정 → 권한 설정하기 → 복사한 텍스트 읽기 → 항상 허용으로 변경.
3. 민감하지 않은 `ACE 읽기 테스트 123`만 복사하고 채팅으로 `클립보드에 복사한 텍스트 읽어줘` 요청. 추가 승인 없이 같은 텍스트를 답하는지 확인.
4. `클립보드에 ACE 새 텍스트 저장해줘` 요청. 저장 승인창에서 취소하면 기존 내용 유지, 새 요청을 승인하면 새 내용으로 바뀌는지 확인.
5. AI가 도구 호출 자체를 반환하지 않는 문제는 별도임. 이 경우 Native 결과가 없는 상태이므로 이번 전달 수정만으로 해결됐다고 판정하지 않음.
