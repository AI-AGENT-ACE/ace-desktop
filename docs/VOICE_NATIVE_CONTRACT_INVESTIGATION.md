# 음성·AI Native 연결 오류 조사

기록일: 2026-10-21. 검증 커밋 미기록(기존 로컬 변경 포함). 커밋·푸시·운영 배포 없음.

## 사용자 보고와 확정 원인

| 항목 | 확인한 원인 / 조치 | 검증 범위 |
| --- | --- | --- |
| 화면 캡처 후 음성 로그 400 | 백엔드 CreateVoiceLogDto가 system.status/app.open/app.close/unsupported만 허용하던 구형 목록. 현재 24개 Native 도구+기존 상태 명령을 허용하도록 수정 | DTO 자동 검증 통과. 실제 새 음성 캡처 후 로그 저장은 사용자 재확인 대기 |
| 전체 캡처의 마지막 버튼 | 선택창이 full/region 모두 수동 완료를 요구했음. full은 컨텍스트 로드 후 한 번 자동 완료. region은 드래그·캡처 유지 | Chrome 모의 IPC에서 자동 완료 1회·region/Esc 유지 통과. 새 동작의 실제 Windows 캡처는 미검증 |
| 음성 최대화 502 | 제시 로그는 /voice/commands 29~57초 처리 후 실패. Rust 최대화 실행 결과가 아님. 기존 catch가 네트워크/HTTP/형식 오류를 VOICE_PROCESSING_FAILED로 합쳐 과거 정확한 원인은 확정 불가 | 진단/오류 분류 자동 시험 통과. 실제 마이크 재현은 대기 |
| 파일 찾기 거부 | 실제 AI 응답에서 위치를 생략하면 directory 필드가 없음. 백엔드는 필수로 요구했음. 위치 없는 검색을 로컬 Known Folder 선택으로 전달 | 실제 AI 응답 확인 + 계약/Chrome 모의 IPC 검증. 사용자 파일은 열거나 검색하지 않음 |
| 파일 열기 거부 | 실제 AI는 query/directory/extensions 검색 의도를 전달하지만 백엔드는 path/resourceId만 허용. 검색 의도 스키마와 기존 파일 대상 선택 UI를 연결 | 원본 요청 정보로 자동 검색 후 실제 Rust resourceId를 선택해야 실행. ASK는 대상 선택 후 유지. Chrome 모의 IPC 통과 |

위치가 없는 검색은 바탕화면·다운로드·문서·사진·음악·동영상 중 하나를 선택한다. 성공한 파일 검색 결과를 메인 창에 표시하고, 결과의 파일 열기는 별도 권한 확인·실행 요청으로 처리한다. AI가 경로를 만들어 곧바로 실행하지 않는다.

## 실제 AI 서버 텍스트 API 조사

사용자가 연결한 AI 서버 `/agent/text`에 테스트 문장 4개와 사용자 제공 파일명 요청 2개를 보냄. 이 조사에서 응답한 도구를 Windows에서 실행하지 않았고, 실제 파일 내용/음성/토큰을 출력하지 않음.

- 바탕화면 테스트 PDF 찾기: 200, 25.096초. file.search + directory/query 객체.
- 바탕화면 테스트 PDF 열기: 200, 27.060초. file.open + query/directory/extensions.
- 메모장 창 최대화: 200, 29.381초. app.maximize + canonicalId=notepad. 기존 appName 정규화 후 카탈로그 검증 통과.
- “볼륨 꺼줘”: 200, 28.662초. **app.close + original=볼륨**으로 잘못 해석. 음소거가 아니라 앱 종료 의도로 반환한 AI 문제. 이 응답을 실행하지 않음.
- 위치 없는 사용자 제공 PDF 찾기: 200, 24.093초. file.search의 directory 없음.
- 바탕화면 사용자 제공 PDF 열기: 200, 23.404초. file.open의 query/directory/extensions.

이는 텍스트 API 관측이며 실제 음성 인식·STT·TTS·음성 API 처리시간과 동일하다고 판단하지 않는다. 다만 백엔드/Windows를 거치지 않은 요청도 23~29초 걸렸다는 근거다. “볼륨 꺼줘” 이후 다른 요청이 실패한 인과관계는 확인되지 않았다. 제공한 401 이후 refresh 200은 정상 갱신 흐름이며 그 자체를 502 원인으로 단정하지 않는다.

## 음성 실패 처리 보완

- 서버의 HTTP 상태/네트워크/타임아웃/잘못된 JSON을 내부 분류. VOICE_AI_RESPONSE/VOICE_AI_FAILED에 recordingId, 단계, 소요 시간, 고정 오류 코드·상태만 기록함. 음성 원문·오디오·파일 경로·비밀값·AI 응답 본문은 기록하지 않음.
- 인자 계약 거부 로그는 알려진 도구 이름과 고정 인자 키·알 수 없는 키 개수만 기록함. 인자 값과 임의 키 이름은 제외함.
- 공개 오류 코드: VOICE_TIMEOUT, AI_SERVER_UNAVAILABLE, VOICE_INVALID_RESPONSE, 기존 VOICE_PROCESSING_FAILED. Orb에서 구분된 한국어 안내.
- 데스크톱 음성 POST의 자동 업로드를 최대 3회에서 1회로 변경. 동일 녹음의 느린 처리를 자동 반복하지 않고 사용자의 새 요청으로 재시도함. 성공/실패 불명인 POST 재전송 방지.
- 기본 데스크톱 응답 대기는 60→75초로 조정해 기본 60초인 백엔드의 분류된 오류를 전달받을 여유를 둠. AI 연산 성능을 개선하거나 서버 응답 속도를 높였다는 뜻은 아님. 기존 명시 환경변수 설정은 유지.

## 자동 검증

- 백엔드 4개 관련 suite, 최종 15개 통과: 24개 로그 도구 허용·임의 명령 거부, 실제 AI 파일 인자/위치 생략 계약, 최대화 인자 정규화, 안전 진단 로그, HTTP/JSON/네트워크/타임아웃 분류. HTTP와 AI 응답은 모의 값이며 실제 음성 시험 아님.
- Chrome 모의 API/IPC: 전체 캡처 추가 클릭 없이 완료 1회, region 좌표/Esc, 파일 열기 검색 결과→resourceId, 위치 없는 검색→폴더 선택→ASK→검색 결과 표시 통과. 겹치는 재실행은 합산하지 않음.
- TypeScript·프런트 production 빌드·개발 패널 제외 검사·백엔드 빌드 통과. Rust 공개 오류 코드 단위 시험과 cargo check 통과.
- 실제 Windows의 최신 전체 캡처 자동 완료·마이크 업로드·음성 최대화·24개 도구 종단 실행은 이번에 시험하지 않음. 이전 사용자/CLI 통과 기록을 그대로 유지하며 이번 변경으로 전체 재검증했다고 표시하지 않음.

## AI 담당 측 확인 필요

- “볼륨 꺼줘”, “소리 꺼줘”가 `system.volume.mute`와 `{ "mute": true }`를 반환하도록 도구 선택 보완. 문자열 "true"가 아닌 boolean 사용.
- /agent/voice 내부의 업로드/STT/Agent 처리 단계별 소요 시간과 5xx 원인을 확인. 현재 텍스트 요청 자체도 23~29초인 구간의 모델/대기/콜드 스타트 확인.
- AI repo 수정·설정 변경·배포는 이번에 진행하지 않음. 로컬에서 계약을 완화해 잘못된 app.close를 음소거로 임의 전환하지 않음.

## 다음 사용자 시험

1. 수정된 로컬 백엔드와 개발 앱을 재시작한다. 운영 앱/서버에는 아직 이 변경이 배포되지 않았다.
2. 음성 없이 Native 테스트 패널 → `앱 창 최대화` → 테스트 메모장 선택: 실제 최대화 여부 확인. 정상이라면 AI/음성 경로와 Windows 창 제어를 분리할 수 있음.
3. 개인 정보가 없는 테스트 화면에서 전체 캡처 요청 → 필요한 기존 승인/모니터 선택 후 마지막 캡처 클릭 없이 결과가 나오는지 확인. 영역 캡처는 기존 방식 유지.
4. 테스트 PDF를 만들어 `바탕화면에서 ACE_테스트.pdf 열어줘` → 검색 결과 선택 → 필요한 권한 승인 → 열기 확인. `ACE_테스트.pdf 찾아줘`는 위치 선택 후 결과 목록 확인.
5. 음성 가능 시 한 번만 최대화 요청. 실패하면 서버의 VOICE_AI_FAILED 단계·reason·upstreamStatus·durationMs와 오류 코드를 확인. 음성 원문이나 비밀값을 공유할 필요 없음.

사용자 O=정상, E=오류, D=애매함, 무표시=이번 목록에서 미시험을 유지한다. 이전에 수동 통과한 파일/캡처 시나리오를 무표시 때문에 취소하지 않는다. 이번 음성 app.maximize E는 새 수동 성공 근거 전까지 통과로 바꾸지 않는다.
