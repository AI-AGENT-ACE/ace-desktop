# fix(wake): 음성 등록 입력 통일과 실제 호출 검증

대상: `main` ← `fix/wake-native-enrollment` (Draft)

## 사건

등록 테스트는 성공했지만 일상 대기에서는 ACE를 여러 번 불러도 후보가 생기지 않았다. 민감 설정에서도 재현됐다.

## 원인 분석

등록은 WebView, 상시 감지는 CPAL로 입력 경로가 달랐다. 등록에 버튼 조작 전후 무음이 포함됐으며, 기존 테스트는 녹음 뒤 합성 무음을 붙인 재생 검사여서 실제 스트림의 감지를 보장하지 못했다. 이전 모델의 참조 프레임은 141~159, RMS는 0.002009였다.

## 해결 방안

- 등록/상시 입력을 네이티브 CPAL 경로로 통일하고 장치 선택과 모노 변환을 공유했다.
- 등록 녹음의 무음 경계를 정리하되 발화 양끝 120ms를 남겼다.
- 모델 적용 전에 실제 입력으로 2회 연속 감지하는 검증을 추가했다. 합성 무음으로 통과시키지 않는다.
- 감도 설정과 gate 진단을 제공하고 과도한 임계값 완화는 하지 않았다.
- 포맷 검사에 맞춰 네이티브 모듈 선언 순서도 정리했다.

## 결과

이 브랜치만 별도 체크아웃하여 Rust 테스트 44개 통과, 7개 제외 및 fmt 통과를 확인했다. 제외 항목은 비공개 음성 fixture 6개와 물리 마이크 1개다. 등록 UI 회귀 테스트도 추가했다.

사용자 후속 로그에서 새 모델의 참조 프레임 66~81, RMS 0.019708, 실제 등록 테스트 2회 성공을 확인했다. 상시 호출도 기본 임계값 0.52에서 0.6567로 감지되어 오브가 열렸다. 이는 사용자 제공 로그이며 개발 도구의 물리 마이크 재현 결과가 아니다. 장기간 인식률/오탐률 측정은 남아 있다.

음성 세션과 오브 UI 변경은 후속 PR에서 다룬다. 전체 경과는 `docs/WAKE_WORD_TROUBLESHOOTING.md` 참고.
