# fix(voice): 오브 표시 안정화와 음성 재시도·확인 흐름 개선

대상: `feat/local-voice-portfolio` ← `fix/voice-orb-session` (Draft)

## 사건

Wake 호출 후 오브가 상태 변화마다 깜빡였다. 명령이 “포트폴리오예요”로 인식되면 빨간 오류 상태로 남았고, 사용자가 닫기 전까지 Wake 대기도 재개되지 않았다.

## 원인 분석

상태별 반복 애니메이션과 문구 변경 시 재마운트가 적용돼 있었다. 요청 전달과 실제 실행 완료를 연결하는 응답 경로가 없었으며, 실패 재청취/자동 종료 정책이 없었다. 오인식 원본 WAV가 남아 있지 않아 발음이나 모델을 단독 원인으로 확정할 수는 없다.

## 해결 방안

- 호출 때만 480ms 등장 효과를 적용하고 상태 전환 중 오브와 말풍선을 유지한다. 중심부와 주변 층의 가시성을 높인다.
- 왼쪽 위 말풍선에 문구/최대 3개 선택지를 표시하고 알림음 ON/OFF 설정을 추가한다.
- 실제 성공 응답 후 3초 종료, 실패 후 5초 재청취를 구현한다. 기한 직전 시작한 발화는 이어 듣고 실패하면 반복한다. 기존 30초 녹음 상한을 유지한다.
- 확인 대기는 유지하며 버튼과 음성 네/아니오/번호를 처리한다. 짧은 확인 발화의 최소 유성 시간을 250ms에서 120ms로 줄인다.
- 요청 ID와 세대 번호로 늦은 결과/중복 선택을 거부한다. 수동 닫기와 메인 창 확인에도 마이크를 정리한다.
- Whisper beam 5/8 비교 기능을 추가했으나 정확도 개선 근거 없이 지연이 늘어 기본 5를 유지한다.
- 회귀 테스트를 CI에 추가하고 `.local/**`를 Vite 감시에서 제외한다.

## 결과

- Rust 47 통과, 7 제외; fmt/Clippy 및 TypeScript/Vite 통과.
- 오브 세션 8, 기존 음성 회귀 4, 등록 UI 회귀 2 통과.
- 기존 보관 녹음 1개의 beam 5/8 비교: 6,262ms/7,527ms, 모두 포트폴리오 명령으로 분류하지 않음. 최근 실패 명령의 정확도 개선을 입증하는 실험은 아님.
- 자동 검사는 오디오/IPC 경계를 모킹한다. 실제 Windows 화면 캡처는 접근 거부로 완료하지 못했다. 실제 재호출, PDF 열기, 소리 ON/OFF, 재청취와 선택 UI 확인이 남아 있으므로 Draft로 유지한다.

자세한 전후 수치와 제한은 `docs/WAKE_WORD_TROUBLESHOOTING.md`의 7~11절에 기록했다.
