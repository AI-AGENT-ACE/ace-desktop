## 이번 실제 시험과 수정

- 패널에 file.search/open/rename, folder.search/open/create, web.open/search 8개 추가. localhost·Tauri 제한, ACE-Native-Test 접두사/단일 이름 제한 및 기존 권한·승인 경로 유지.
- 검색은 desktop 전체 순회가 아니라 `격리폴더/정확한이름` 인자를 사용. Rust의 기존 상대경로 검색 경로에서 경계 검증.
- app.open/maximize와 기존 복사·이동 실패→DB 시험은 통과 근거가 있어 반복하지 않음.
- `open_with_shell`이 explorer.exe 프로세스 생성만 확인하던 방식을 ShellExecuteW의 등록 핸들러 호출/반환 코드 검사로 변경. HTTP(S) 제한·검색어 URL 인코딩·파일 경계 검증은 기존 실행부 유지. OS의 열기 요청 수락이 페이지 로드 완료를 보장하지 않으므로 이번에는 별도로 Windows UI Automation으로 Chrome 탭과 탐색기/메모장 결과를 확인.
- 이름 변경은 승인 후 source.txt가 사라지고 renamed.txt의 SHA-256이 기존 source와 같음. 폴더 생성은 승인 후 created 디렉터리 존재 확인.
- 파일 열기 직후 이름 변경한 초기 자동화에서는 메모장이 읽기 전에 파일명이 바뀌어 경고 발생. 제품 파일 열기 성공으로 기록하지 않고 새 격리 파일로 열기만 분리하여 테스트 문장 표시 확인. 일부 UIA FindText 미지원 요소는 있었으나 지원되는 요소에서 정확한 테스트 문장 일치 확인.
- 초기 결과만으로 웹 통과를 판정하지 않음. 수정 후 Chrome의 Example Domain과 ACE native verification Google 검색 UI, 격리 child 탐색기 표시 확인 후 정상 실행으로 기록.
- 자동화 수정 명령의 인용 오류로 첫 묶음이 한 차례 중복 실행됨. 시험 수를 합산하거나 별도 추가 커버리지로 계산하지 않음.

증거 파일(로컬, 비밀값 미포함): `.local/native-matrix-result.json`, `.local/native-matrix-file-open.json`. 실제 attemptId와 UI 상태 포함. 이번 기록은 HTTP execution 이벤트 관찰이며 DB 직접 조회 결과는 아님. 기존 OVERWRITE_LOCAL_DB_VERIFICATION.md의 실제 DB 증거는 그대로 유지.

검증: TypeScript, 프런트 빌드 및 운영 산출물 Native 패널 제외, cargo check 통과. Rust 실제 개발 앱 재빌드·실행 통과. 프런트 빌드의 기존 큰 청크 경고 유지. 새 Windows 실패/차단 시나리오를 합성 응답으로 통과 처리하지 않음.

## 직접 확인이 남은 범위

이번 후보 8개의 정상 실행에는 추가 사용자 조작 불필요. AI 채팅의 파일·웹 해석 오류는 별도 수정 대기이며 패널 성공으로 해결 처리하지 않는다. 개별 명령의 DENY/ASK 취소·미존재·중복·접근 거부 범위는 위 표대로 대기. 음성·클립보드·볼륨·잠금·다중 모니터·설치/업데이트·운영 검증은 이번에 수행하지 않음.

테스트 폴더는 개인 파일과 구분하여 보존하며 자동 삭제하지 않음. Windows 코드 서명과 객체 저장소의 의도적 보류 유지. 커밋·푸시·배포 없음.
