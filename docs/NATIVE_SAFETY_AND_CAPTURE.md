# Native 안전 실행과 화면 캡처 — 4~7번 작업

2026-10-13 로컬 구현·검증 기록. 기존 변경을 보존했으며 커밋·푸시·배포는 하지 않음.

## 이전 1~3번의 완료 상태 유지

- 공용 Wake Word 모델은 아직 없음. 실제 녹음·재배포 동의·여러 사람의 호출 성공/오탐 평가·새 PC 설치 시험은 대기. 파일 검증을 정확도 검증으로 취급하지 않음.
- USB 마이크 선택 후 실제 녹음/호출, 연결 해제와 다른 장치 재선택은 수동 검증 대기. 모의 이벤트 검사는 실제 음성 시험을 대체하지 않음.
- 실제 앱의 여러 창 선택, 미저장 문서와 앱별 저장/세션 복원 동작도 수동 검증 대기. 전용 테스트 창의 자동 검증과 구분함.
- 기존 기록은 [VOICE_INPUT_AND_WINDOWS.md](VOICE_INPUT_AND_WINDOWS.md)에 유지. 공용 모델이 없는 Release 빌드는 계속 명확한 오류로 차단됨.

## 4. 선택 창 정상 종료

- 기존 Rust의 대상 ID와 WM_CLOSE 정상 종료 요청을 재사용함. 프로세스 강제 종료는 추가하지 않음.
- 요청 발송 결과는 closeRequested, 실제 창 종료 여부는 별도 일회성 관찰 티켓으로 확인함. 같은 창·프로세스 식별이 유지되는지 최대 5초간 확인함.
- 창이 남아 있으면 “저장 확인 또는 사용자 조작이 필요합니다” 표시. 완료 결과를 종료 요청과 실제 종료로 구분해서 전달함.
- 저장 확인창을 조작하지 않으며 자동 저장·세션 복원 때문에 확인창이 없는 상황도 허용함.

## 5. 파일 덮어쓰기

- file.copy / file.move / file.rename 충돌 시 원본·대상 경로와 크기를 표시하고 취소 / 다른 이름 지정 / 덮어쓰기 제공.
- 충돌 확인 ID는 승인 토큰이 아님. 사용자가 덮어쓰기를 선택하면 main 전용 IPC로 별도 토큰 발급.
- 토큰은 명령·정규화한 경로·인자·파일 지문·만료시간에 결합되고 한 번만 소비됨. confirmed: true 또는 최초 확인 ID만으로 교체 불가.
- 지문은 파일 ID·볼륨·크기·변경 시각·SHA-256 기준. 승인 발급 및 실행 시 다시 검사하고 변경·만료·변조 시 중단 후 재확인.
- 현재 안전 교체는 같은 볼륨의 Transactional NTFS가 실제 동작하는 경우만 지원. 기존 대상부터 삭제하지 않으며 대상 쓰기와 원본 삭제 의도를 하나의 트랜잭션에서 확정함. 이동 원본은 대상 쓰기 완료 후에만 삭제 의도 설정.
- 실패하면 트랜잭션 롤백으로 원본·기존 대상 보존. 일반 복사 실패는 이번 작업이 독점 생성한 임시 파일만 정리.
- 교체는 512 MiB 이하의 일반 단일 링크 파일만 지원. 다른 볼륨, 재분석 지점, 하드 링크, 대체 데이터 스트림, 공유 잠금 또는 트랜잭션 미지원 상황은 거부. 일반 새 이름 복사는 대체 스트림을 보존.
- TxF는 미래 Windows에서 제공되지 않을 수 있어 범용 지원을 약속할 수 없음. 기능을 강제로 켜거나 비트랜잭션 교체로 자동 전환하지 않음. [Microsoft 안내](https://learn.microsoft.com/en-us/windows/win32/fileio/about-transactional-ntfs).

## 6. 휴지통 이동만 허용

- file.delete는 IFileOperation의 명시적 휴지통 플래그와 진행 콜백으로 처리함. 휴지통 삭제 표시가 없으면 작업을 거부하고, 완료 후 생성된 휴지통 항목도 확인함.
- 일반 로컬 고정 드라이브 파일만 지원. 심볼릭 링크·재분석 지점·네트워크/이동식 드라이브 등은 오류 반환.
- 실패·휴지통 미지원 시 영구 삭제로 전환하지 않음. 영구 삭제 명령 없음.
- 실제 시험에서 앱이 새로 만든 43바이트 테스트 파일 1개를 휴지통으로 이동했음. 사용자 휴지통을 비우지 않았으며 이 테스트 파일은 복구 가능한 상태로 남겨 둠.

## 7. 모니터/영역 캡처

- screen.capture 요청 시 모니터 목록에서 전체 또는 영역 선택. UI에는 임시 모니터 ID를 전달하고 위치·배율은 Rust에서 관리.
- 영역은 선택한 모니터 안에서만 드래그. 논리 좌표를 모니터 배율로 물리 픽셀에 변환하고 왼쪽/위쪽 음수 원점도 반영함.
- 전용 선택창에 캡처 제외 설정을 적용하고, 촬영 직전 숨김·가시성 검사·DWM 합성 완료를 확인. 제외 설정 실패 시 촬영 거부.
- Esc, 입력창의 중지, 창 닫기, 모니터 연결/배율/위치 변경, 3분 선택 만료 시 취소. 연결 상태는 작업 중 및 촬영 전후 재검사.
- 취소·실패·미소비 결과는 이번 작업이 독점 생성한 이미지 파일 핸들로 정리. 같은 경로에 원래 있던 파일은 생성 실패 처리하며 삭제하지 않음.
- 완료 결과는 앱 캐시의 capture-temp에 남기고 이미지 열기 버튼 제공. 사용자가 다른 위치에 저장한 이미지에 대한 자동 삭제 없음. 성공 이미지 자동 만료 정리는 이번 작업에 포함하지 않음.

## 음성 없이 사용자가 확인할 순서 — 수동 검증 대기

1. 개발 앱에서 같은 앱의 독립 창 3개를 열고 텍스트로 종료 요청 → 선택한 창만 정상 종료 요청되는지 확인. 미저장 창이 남으면 5초 뒤 안내 확인. 확인창이 없고 정상 종료되는 앱은 실패로 판단하지 않음.
2. 바탕화면에 테스트용 폴더를 만들고 서로 다른 내용의 작은 a.txt / b.txt 준비. 텍스트 파일 검색으로 대상 선택 후 복사/이동/이름 변경 요청. 취소·다른 이름·덮어쓰기 각각 확인. 실제 중요한 파일은 사용하지 않음.
3. 충돌 선택창을 띄운 뒤 테스트 원본 또는 대상을 편집·저장하고 덮어쓰기 → 변경 거부 및 재확인 확인. 지원하지 않는 볼륨은 거부되는 것이 기대 동작.
4. 새 테스트 파일 삭제 → Windows 휴지통에서 복구 가능 여부 확인. 미지원 위치에서 오류 반환과 원본 유지 확인. 휴지통 전체 비우기는 필요 없음.
5. 텍스트로 화면 캡처 요청 → 모니터 전체 또는 영역 선택 → 이미지 열기로 결과 확인. Esc/중지 후 선택창 종료 확인.
6. 실제 다중 모니터에서 서로 다른 배율, 왼쪽/위쪽 배치, 모니터 연결 해제 상황 확인. 현재 자동 검사의 가상 좌표 검증만으로 하드웨어 검증 완료 처리하지 않음.

실제 Tauri 앱에서 AI가 해당 명령을 생성한 뒤 승인·모니터 선택까지 이어지는 전체 흐름, 앱별 저장 확인창, 실제 다중 모니터 및 장치 연결 해제는 수동 검증 대기임. 1~3번 음성·새 PC 완료 조건도 그대로 대기함.

## 검사 명령

```powershell
cargo test --manifest-path ./ace-desktop/src-tauri/Cargo.toml --lib
cargo clippy --manifest-path ./ace-desktop/src-tauri/Cargo.toml --all-targets -- -D warnings
cargo build --manifest-path ./ace-desktop/src-tauri/Cargo.toml --bin ace-desktop
```

다음 명령은 ace-desktop을 작업 디렉터리로 사용:

```powershell
node --experimental-vm-modules --test scripts/test-orb-session.mjs scripts/test-voice-regression.mjs scripts/test-wake-default.mjs
npm run build
npx playwright test --config playwright.input.config.ts
```

제외된 GUI/음성 테스트 전체를 한꺼번에 실행하지 않음. GUI 검사는 해당 테스트 이름을 지정해 개별 실행했으며 음성 입력 테스트는 실행하지 않음.
