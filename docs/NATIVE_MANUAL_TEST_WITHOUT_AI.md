아래는 대화에서 보고된 사용자 결과와 기존 검증 기록을 구분한 현황이다. 아래쪽 시험 절차는 실행 안내이며 통과 기록이 아니다. 이번 문서 정리에서는 테스트를 재실행하지 않았다. 서로 겹치는 테스트 실행 수는 합산하지 않는다. 과거 버전 통과를 현재 설치 앱·운영 서버 통과로 확장하지 않는다.

### 모의 API·IPC 및 자동 테스트 결과

실제 브라우저 UI를 조작했어도 아래 테스트의 서버/Native 응답은 모의 응답이다. Windows 작업 성공·운영 배포·설치 앱 성공을 뜻하지 않는다.

- 기존 Native 안전성·입력창 시나리오 26개 통과: 승인/대상 선택/캡처 성공·실패·취소 등. 관련 기록: [가독성 검증](APPROVAL_CAPTURE_READABILITY.md).
- 마지막 복사·이동 버튼 변경 후 다른 이름·확장자 시나리오 5개 통과: 확장자 자동 보완·중복 방지·변경 확인·이전 승인 폐기. 실제 파일 교체 성공의 증거는 아님.
- 한국어 권한 그룹·안내 및 입력창 회귀 10개, 서버 오류 코드 안내 추가 2개 통과. DENY와 UNKNOWN_TOOL 분리, 설정 이동, 미지원 기능의 권한 변경 안내 제거 확인.
- 라이트·다크 권한 알림 버튼 테스트 2개 통과: 기본/hover/pressed/키보드 focus 대비 4.5:1 이상, X 색·접근성 이름·닫기 동작 확인. 실제 브라우저 스크린샷 확인.
- 대화 삭제 6개 통과: 현재 대화, 다른 대화, 실패, 삭제 대기 중 이동, 지연 메시지 조회, 지연 AI 응답. 선택·본문·입력 정리/유지, 빈 대화 선생성 없음 확인.
- 휴지통 취소→재삭제 성공/실패 2개 통과: 취소 시 요청 없음, 영구 삭제 1회, 일반 목록 재요청·스켈레톤·항목 재마운트 없음, 선택·입력·스크롤 유지, 실패 시 항목 유지. 실제 브라우저 화면 확인.

빌드·정적 검사·순수 단위 테스트는 위 실제 DB/Windows 검증과 별개다. 기존 TypeScript·프런트 빌드·개발 패널 운영 산출물 제외·Cargo check 통과 기록, 승인 단위 테스트 3개, 앱 닫기 처리 순서 테스트, 경로/캡처 수명 관리 단위 테스트는 구현 검증 근거로만 사용한다. 최신 UI 변경 이후에는 해당 변경의 TypeScript·브라우저 검사만 실행한 경우가 있으므로 최신 전체 Release 빌드 완료로 기록하지 않는다.

승인 단위 테스트 3개는 호출 창·시도·대상 결합, 만료/중복, 인자·대상 스냅샷 변경·재사용 거부를 확인한 기존 근거다. 다른 창에서의 승인 사용·일회성 승인 재사용 차단은 이 자동 테스트 범주에 기록하며 실제 설치 앱 전체 흐름 통과로 간주하지 않는다.

### 미검증·대기 또는 의도적 보류

- 음성: 최신 녹음·마이크 교체/해제/재연결·Wake Word·Orb 음성 흐름은 대기. 과거 사용자 호출 성공으로 대체하지 않음.
- 공용 Wake Word 모델: 재배포 동의·공용 모델 파일·여러 사람 평가 기록 미준비. Release 검증 실패 조건 유지. 새 PC 설치 직후 호출 완료 판정 보류.
- Windows 창: 메모장 저장 확인창 취소 후 문서·창 보존은 사용자 통과. 다른 앱과 앱별 자동 저장·세션 복원 동작은 대기. 실제 포커스 실패/상실 조건 전체는 처리 순서 자동 테스트와 구분.
- 파일: 실제 잠금·ADS 거부, 합성 오류 TxF 롤백·핸들 정리 및 OS 잠금 실패의 실제 앱→로컬 DB 추적은 통과. 실제 디스크 부족·장치 I/O·커밋 실패와 해당 오류의 DB 흐름, 비NTFS/네트워크 볼륨은 대기. 기존 지원 제한·안전 정책 유지.
- 캡처: 실제 다중 모니터·서로 다른 배율·음수 좌표·모니터 해제와 장시간 실제 미리보기의 lease 유지 시험은 대기. 격리 ACE 프로세스 재시작/주기 정리·저장 사본 바이트 보존은 CLI 통과. 일반 캡처·영역·사용자 저장 자체는 수동 통과. 설치 앱 재검증으로 확대하지 않음.
- Native 24개 명령 전체 검증은 대기. 위 일부 명령·시나리오의 통과로 전체 완료를 선언하지 않음.
- 자동 업데이트: 실제 서명 키·Release 산출물 준비 및 이전 설치 버전→새 버전, 변조 거부, 작업 중 설치 연기, 설정 유지 대기.
- Windows 코드 서명: 인증서·예산 없음. 미적용·후속 작업. 자체 인증서를 공인 서명의 대체로 사용하지 않음.
- 운영: 최신 로컬 변경의 Render·Neon 적용, 운영 migration/백업 복원/CORS/Health/콜드 스타트는 확인 근거 없음. 과거 Live·v0.1.2 보고는 최신 변경 배포 증거 아님.
- 장기 보존 첨부: 사용자 확인상 없음. 객체 저장소 도입은 보류하며 미구현 결함으로 재등록하지 않음.

### 배포 전 남은 비음성 검증 우선순위

1. **메모장 문서 보존 — 수동 통과:** 단일 대상 승인·포커스·저장 확인 취소 후 보존은 재시험 불필요. 포커스 실패/상실 등 미확인 예외만 별도 시나리오로 관리.
2. **P0 — 파일 실패 안전성:** 합성 오류 롤백·실제 잠금/ADS 거부 및 잠금 실패의 앱→DB 기록은 통과. 다른 파일 시스템·장치 오류 조건은 별도 준비 후 검증. 디스크를 채우는 위험 시험은 권하지 않음. 기존 통과 시나리오는 관련 변경 없이 반복하지 않음.
3. **P0 — 운영 데이터 변경 전:** 별도 DB로 백업 복원 시험, 실제 배포 예정 migration과 운영 적용 기록 비교 및 보존/복구 계획 확인. 운영 접근·적용은 별도 승인 전 실행하지 않음. 이미 통과한 로컬 7개 테스트를 단순 반복하지 않음.
4. **P1 — 캡처·로컬 자원:** 격리 앱의 강제 종료 후 정리·저장 사본 보존은 통과. 실제 장시간 미리보기와 다중 모니터·배율·연결 해제는 별도 준비 후 검증. 통과한 전체/영역 캡처·사용자 저장은 단순 반복하지 않음.
5. **P1 — 명령 범위:** 24개 명령 중 별도 실기기 통과 기록이 없는 명령부터 범위를 정해 확인. 프로필·대화/휴지통·권한 변경·로컬 서버 재연결의 통과 시나리오는 새 변경/실패 근거 없으면 반복하지 않음.
6. **P1 — 설치·업데이트 배포 조건:** 모델/업데이트 서명 준비 후 새 Windows PC 설치, 개발 패널 제외·버전 일치·설정 보존, 실제 이전 버전 업데이트·변조 거부·작업 중 연기 확인. 준비 전 Release 성공 처리 금지. 코드 서명은 미적용 사실을 명시하고 별도 후속 관리.

통과한 테스트는 관련 코드·계약·의존성 변경이나 새로운 실패 근거가 있을 때만 재실행한다. 위 순서는 미확인 경계의 검증 우선순위이며, 이번 문서 정리에서 커밋·배포·DB 작업·수동 Windows 조작을 수행하지 않았다.

### 통과한 수동 시험의 참고 절차: 저장 확인 취소 (재실행 불필요)

1. 개인 문서 대신 새 메모장 테스트 문서를 열고 식별할 문장을 입력하되 저장하지 않는다. 다른 개인 문서는 닫기 대상으로 선택하지 않는다.
2. 개발 패널의 앱 창 정상 종료에서 그 테스트 창만 선택하고 최종 승인한다.
3. 저장 확인창이 나타나면 ACE가 대신 조작하지 않는지 확인한 뒤 사용자가 `취소`를 누른다.
4. **통과 기준:** 확인창이 사용자 조작 전 유지되고, 취소 후 같은 창과 입력 문장이 남으며, ACE가 강제 종료하거나 다른 창에 재실행하지 않는다. 창이 남으면 사용자 조작 필요 안내가 표시된다.
5. 자동 저장·세션 복원 설정 때문에 확인창이 없으면 실패로 단정하지 말고 이 세부 시험은 `해당 조건 미재현·대기`로 기록한다. 앱 버전·관련 설정도 함께 기록하고, 개인 문서로 시험하거나 자동 저장 설정을 임의로 바꾸지 않는다.

이하 절차는 참고용 기존 가이드다. 위 수동 통과 항목을 다시 수행하라는 작업 목록이 아니며, 관련 변경 또는 새 오류가 있을 때 해당 부분만 사용한다.

## 테스트 파일 준비

별도 PowerShell 터미널에서 아래를 한 번 실행. Windows가 지정한 실제 바탕화면에 매번 새로운 폴더를 만들며 개인 파일을 덮어쓰지 않음.

```powershell
$nativeTestName = 'ACE-Native-Test-' + [guid]::NewGuid().ToString('N').Substring(0,8)
$nativeTestRoot = Join-Path ([Environment]::GetFolderPath('Desktop')) $nativeTestName
New-Item -ItemType Directory -Path $nativeTestRoot -ErrorAction Stop | Out-Null
$nativeTestFiles = @{
  '원본.txt' = 'COPY SOURCE'
  '대상.txt' = 'KEEP ORIGINAL TARGET'
  '이동원본.txt' = 'MOVE SOURCE'
  '이동대상.txt' = 'KEEP MOVE TARGET'
  '삭제용.txt' = 'RECYCLE TEST'
  '창-A.txt' = 'TEST WINDOW A'
  '창-B.txt' = 'TEST WINDOW B'
  '창-C.txt' = 'TEST WINDOW C'
}
foreach ($entry in $nativeTestFiles.GetEnumerator()) {
  Set-Content -LiteralPath (Join-Path $nativeTestRoot $entry.Key) -Value $entry.Value -Encoding UTF8
}
Write-Output "패널에 입력할 테스트 폴더 이름: $nativeTestName"
Write-Output "테스트 폴더: $nativeTestRoot"
```

패널에는 출력된 **폴더 이름만** 입력. 전체 경로나 `..`는 입력하지 않음. 다른 이름 충돌 시험을 새로 시작하려면 이 명령으로 별도 폴더를 만들면 됨. 기존 파일 복구·정리를 위해 개인 파일을 지울 필요 없음.

## 앱 창 선택·최소화·포커스·정상 종료

- 메모장의 독립된 창 3개를 열고 각각 테스트 폴더의 `창-A.txt`, `창-B.txt`, `창-C.txt` 열기. 한 창의 탭 3개는 창 3개가 아니므로 별도 창으로 분리.
- 개발 패널 `테스트 작업` → `앱 창 최소화`, `앱 이름` → `notepad` → `테스트 요청`.
- 정책상 확인이 나오면 허용. 메인 창 오른쪽 위 `작업할 창 선택`에서 제목을 보고 `창-B.txt` 선택. 해당 창만 최소화되는지 확인.
- `앱 창 포커스`도 같은 방식으로 선택. Windows가 전경 전환을 거부하면 권한 오류가 반환될 수 있으며 보호 정책을 우회하지 않음.
- `앱 창 정상 종료` → 대상 선택 → Rust가 표시한 창 제목 확인 → `허용`. 저장 확인창이 있으면 직접 취소해 문서가 유지되는지 확인.
- 종료 후 최대 5초 동안 같은 창이 남아 있으면 `저장 확인 또는 사용자 조작이 필요합니다` 안내. 자동 저장·세션 복원 설정으로 저장 확인 없이 닫히는 것은 반드시 실패를 뜻하지 않음. 강제 종료하지 않음.
- 선택창을 띄운 다음 해당 테스트 창을 직접 닫고 선택하면 다른 창에 실행되지 않고 재조회 안내가 나와야 함.

## 파일 복사·이동·이름 충돌

- `파일 복사` 선택 → 테스트 폴더 이름 → 원본 `원본.txt` → 대상 `대상.txt` → `테스트 요청`.
- 먼저 Rust 확인창에서 실제 원본·대상 경로 확인 후 `허용`.
- 충돌이 있으면 오른쪽 위 `파일 덮어쓰기 확인`에 원본·대상 경로와 크기 표시.
  - `취소`: 두 파일 유지.
  - `다른 파일 이름`에 `복사본.txt` 입력 → `다른 이름으로 실행` → 새 경로 승인. 원본·기존 대상은 유지.
  - `덮어쓰기` → 변경된 작업을 다시 `허용`. 지원되는 조건이면 대상 내용 교체.
- `파일 이동`은 원본 `이동원본.txt`, 대상 `이동대상.txt`로 같은 순서. 성공한 이동은 원본이 없어지고 대상에 원본 내용이 있어야 함.
- 충돌창을 띄운 뒤 **테스트 대상 파일만** 메모장에서 수정·저장하고 덮어쓰기 시도 → 변경 감지로 중단·재확인되어야 함.
- 안전 덮어쓰기는 지원되는 동일 볼륨의 Transactional NTFS·일반 파일에 제한됨. 미지원이면 `SAFE_OVERWRITE_UNAVAILABLE` 오류가 정상적인 보호 동작. 이 경우 취소 또는 다른 이름 사용. 전체 Windows 환경에서 덮어쓰기 성공을 보장하지 않음.

## 파일 휴지통 이동

- `파일 휴지통 이동` → 같은 테스트 폴더 → 원본 `삭제용.txt` → 요청 → 표시 경로 확인 → `허용`.
- 폴더에서 파일이 사라지고 Windows 휴지통에서 해당 파일을 찾을 수 있는지 확인. 휴지통의 해당 파일만 복원해 원위치로 돌아오는지 확인.
- 미지원 위치·이동 실패는 오류. 영구 삭제로 전환하지 않음. 휴지통 전체를 비우지 않음.

## 모니터 전체·영역 캡처 / Esc

- `모니터·영역 캡처` → `테스트 요청` → 필요한 권한 확인.
- 오른쪽 위 `캡처 모니터 선택`에서 `모니터 N 전체 캡처` 또는 `모니터 N 영역 선택`.
- 전체: 선택한 모니터의 선택창에서 `캡처` 클릭.
- 영역: **그 모니터 안에서** 드래그한 뒤 `캡처` 클릭. 다른 모니터까지 이어서 드래그하는 기능은 없음.
- 선택창에 포커스가 있는 상태에서 Esc → 취소·선택창 종료 확인. `취소` 버튼도 같은 기능.
- 완료 후 오른쪽 아래 결과에서 `이미지 열기`로 확인. 필요하면 `다른 이름으로 저장` 사용. 저장 사본은 사진 폴더 `ACE Captures`에 남고 임시 정리에서 제외됨.
- 캡처 선택 UI가 결과에 포함되지 않는지, 배율·모니터 위치가 정확한지 확인. 개인 정보가 없는 테스트 창만 화면에 두고 시험.

## 프로필 이름

- 사이드바 하단 톱니바퀴 `설정 열기` → 상단 `프로필` → `표시 이름` 수정 → `프로필 저장`.
- 성공 문구와 사이드바 변경 확인 → 개발 앱을 종료·재실행하고 같은 로컬 계정으로 로그인 → 이름 유지 확인.
- 이메일·비밀번호는 이 프로필 편집 대상이 아님.

## AI 필요 여부와 검증 범위

- 위 개발 패널의 모든 작업, 권한 변경, 프로필 수정: AI 불필요. 로컬 백엔드·로그인·Tauri는 필요.
- 자연어 채팅을 Native 명령으로 해석하거나 AI 후속 답변을 받는 흐름: AI 필요. 이번 AI 비활성 실행에서는 검증하지 않음.
- 패널은 `queueLocalRequest` → 서버 권한/도구 목록 → `/agent/executions` 등록 → 기존 대상 선택/승인 → `execute_native_tool`을 사용. 강제 confirmed 값만으로 Rust 승인을 건너뛰지 않음. 테스트용 실행 IPC·인증 우회·가짜 서버 계정 없음.
- 운영 빌드에서 동적 import와 UI 분기를 제거하며 빌드 마지막에 개발 패널 문자열/모듈 유출 검사. 전용 URL·해시 경로도 추가하지 않음.
- 가이드 작성 당시 UI 자동 검증은 API/IPC 모의 응답 기반이었다. 이후의 실제 Windows CLI 기록과 이번 사용자 수동 통과는 상단에 분리해 반영했다. 이미 통과한 창·파일·캡처 시험은 관련 변경 없이 반복하지 않는다. 이번 기록 정리에서 파일 조작·음성 시험은 실행하지 않음.
