# 채팅 파일 검색 및 중복 결과창 수정

- 사용자 재현: 이름만 요청 시 계약 거부, 바탕화면 검색 후 결과는 있지만 목록 미수신 안내, 검색 결과창 2개 중첩.
- 실제 AI 요청 1회로 `asdf.txt 찾아줘` 재현: file.search, query.original/candidates=asdf.txt, directory.canonicalId=home, extensions=[], limit=20 반환. DB·파일 작업은 실행하지 않고 AI 응답만 확인. 자격 증명은 출력하지 않음.
- 원인: 검색 directoryReference에 home이 빠져 계약 검증 실패. 검색 성공 시 App의 searchPreview와 fileSearchResults를 동시에 설정해 두 창 렌더링. 결과 전송은 일반 완료 summary뿐이라 AI가 실제 로컬 목록을 받지 못했다고 답할 수 있었음.
- 수정: home/drive_c 문자열 및 참조는 검색 계약에서만 허용. 이동/삭제 경로 허용 범위는 유지. 이름 검색의 임의 문장 우회 처리는 추가하지 않음. 위치 생략 시 C 드라이브, AI가 home을 지정하면 사용자 폴더 범위이며 UI에서 범위를 명시. 전체 C 검색과 home 검색을 동일하다고 표시하지 않음.
- 수정: 결과창은 fileSearchResults 한 개로 통일. 위치 없는 검색도 ASK 설정을 존중하도록 불필요한 예외 제거. 결과 선택 전까지 자동 열기 없음, 닫기 한 번으로 목록 종료.
- 수정: 결과 개수/부분 검색/로컬 표시 여부만 백엔드로 전달. 실제 파일명·전체 경로는 보내지 않음. 티켓·결과 검증 이후 검색 완료 안내는 해당 메타데이터로 생성. AI에는 결과 요약을 전달하되 목록 미수신 문구나 AI 연결 실패가 완료된 Native 검색을 실패로 바꾸지 않음.
- 검증: 실제 AI 응답 1건 확인, 백엔드 관련 단위/모의 서비스 검사 12개 통과, Rust home 별칭 단위 검사 1개 통과. Chrome 모의 API/IPC에서 ASK 실행 전 미실행, 승인 후 단일 결과창, 결과 개수 전달·파일명 미전송, 닫기 후 결과창 제거 통과. 처음 UI 검사에서는 테스트 API 주소 설정 누락으로 실패, 모의 주소를 맞춘 뒤 통과.
- 기존 실제 Windows 검색 통과 기록은 유지. 이번 검사는 실데이터 Windows 앱→DB 종단 재검증/음성/설치 앱/운영 배포 성공이 아님. 사용자 최신 실기기 확인 대기. 커밋·푸시·배포 없음.

재시험: 로컬 백엔드와 Tauri 개발 앱 재시작 → 테스트 파일 준비 → 채팅 `asdf.txt 찾아줘`, `바탕화면에서 asdf.txt 찾아줘`를 각각 새 요청 → 필요한 승인 → 결과창 한 개와 완료 안내 확인 → 아무것도 선택하지 않아도 목록 미수신 오류가 나오지 않아야 함 → 닫기 한 번으로 목록 종료. `home` 결과는 사용자 폴더 범위임. AI가 다른 인자를 반환하면 별도 계약 오류로 확인해야 함.
