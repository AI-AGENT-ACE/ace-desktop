# app.close 대상 표시

## 2026-10-19 포커스 실패·단일 대상 보완

- 사용자 실패 기록: executionId `7614e6e8-9a18-401c-8745-dda8798f7c2c`, attemptId `d33941e7-24a6-4b8d-8464-41883ad79c84`, WINDOW_FOCUS_FAILED, 2ms. 기존 코드의 400ms 표시와 WM_CLOSE 전송 이전 포커스 단계에서 중단된 경로. 당시 전면 창·API 반환값은 기록이 없어 Windows 제한과 즉시 판정 오탐 중 어느 원인인지 소급 확정하지 않음.
- 이미 대상이 전면이면 활성화 API 반환값 없이 실제 상태로 성공 판정. 아니면 표준 SetForegroundWindow 1회 요청 후 최대 700ms 동안 20ms 간격으로 실제 전면·최소화 해제 상태 확인. 반복 활성화·AttachThreadInput·설정 변경·강제 종료 없음.
- 최소화된 대상만 복원하며 일반/최대화 상태 유지. 다른 스레드의 복원은 ShowWindowAsync 사용. 동일 스레드 테스트 창은 ShowWindow 사용하여 자기 메시지 큐 대기 문제 방지.
- 승인 검증·소비 이후 app.close dispatch를 UI 스레드에서 수행. 400ms 표시 뒤 대상 동일성과 전면 상태 재검증 후 정상 종료 요청. 저장 확인창은 조작하지 않음. 기존 종료 관찰 5초 유지.
- 실패 문구는 “대상 창을 앞으로 가져오지 못해 종료 요청을 보내지 않았습니다. 창을 직접 확인한 뒤 다시 시도해 주세요.”로 구분.
- 요청한 앱으로 필터링한 유효 창이 하나이면 Rust prepare 단계에서 해당 opaque ID를 승인 인자에 결합. 준비된 인자를 UI에 반환하고 실제 실행에 동일 값 사용. 승인 생략 아님. 여러 개는 선택, 0개는 WINDOW_NOT_FOUND. 실행 직전 대상·프로세스·스냅샷 검사 유지.
- 개발 콘솔에 already_foreground/activation, API 반환값·실제 전면 확인, normal_close_request 전송 여부 기록. 제목·문서 내용·전체 경로는 출력하지 않음. 최종 실행 ID/attemptId는 기존 native-tools.jsonl 감사 기록에 유지.

### 검증 경계

- 후속 사용자 수동 검증 통과: 단일 창 선택 생략, 정확한 대상 승인, 포커스 전환, 저장 확인창에서 취소 후 동일 창·문장 보존. 정확한 시험 일시·커밋 미기록. 아래 CLI 실패·당시 대기 기록은 이력이며 현재 사용자 수동 결과와 구분한다. 다른 앱·자동 저장 설정 전체 통과는 아님.

- 기존 창 대상·실패 순서 Rust 테스트 6개 통과. 단일 후보 결합과 단일 승인/다중 선택/대상 소멸 브라우저 테스트 추가. 브라우저 3개 통과는 모의 API/IPC 결과.
- 실제 Windows 임시 창 GUI 테스트 2개를 명시적으로 실행했으나 활성화 거부로 실패. 동일 스레드 비동기 복원 문제도 확인해 수정했으며 이 실패를 통과로 기록하지 않음.
- 실제 개발 앱에서 새로 만든 메모장 테스트 문서를 선택하고 정확한 제목이 승인창에 표시됨을 확인. 실행 시 Windows 전면 전환이 계속 거부되어 종료 전 중단. UI 스레드 변경 후에도 자동화 환경에서 거부 사례 확인. 종료 성공·저장 확인창 표시/취소 보존으로 기록하지 않음.
- 테스트 도구의 ACE 전면 활성화도 실패한 사례가 있어, 자동화 입력 환경의 영향을 배제할 수 없음. 사용자 직접 클릭 경로의 최종 포커스 성공은 별도 확인 필요. 강제 포커스 우회는 추가하지 않음.
- 당시 CLI에서는 저장 확인창 유지→취소→문장/창 보존 미검증. 후속 사용자가 직접 이 조건을 통과했다. CLI 실행은 종료 전 차단이므로 세션 저장 설정 탓이라고 판단하지 않음.
- 생성한 테스트 문서만 사용했고 기존 개인 문서·메모장 설정은 수정하지 않음. 테스트 문서는 자동 저장/폐기하지 않고 남김. 커밋·푸시·운영 배포 없음.

- 실제 공통 Rust 실행 경로에서 승인된 창 ID를 소비하고 창·프로세스 생성 시각·경로·창 nonce를 재검증함.
- 최소화된 창만 복원하고 SetForegroundWindow 성공 및 실제 foreground HWND 일치를 확인함.
- 400ms 대기 후 대상의 만료·동일성을 재검증하고 foreground 유지 여부를 확인한 뒤 WM_CLOSE를 전송함.
- 포커스 실패 또는 표시 중 포커스 상실 시 WINDOW_FOCUS_FAILED로 중단하고 직접 창 확인 후 재시도를 안내함. 다른 창으로 대체하지 않음.
- 일회성 승인과 기존 권한 검증 유지. 실패 후에는 다시 선택·승인해야 함.
- 기존 실제 종료 관찰 및 5초 후 저장 확인/사용자 조작 필요 안내 유지. 저장 확인창 자동 조작과 강제 종료 없음.

## 수동 확인

1. 개인 문서 대신 테스트용 메모장 창 2개를 열고 한쪽에 미저장 텍스트 입력.
2. 선택할 창을 최소화하거나 ACE 뒤에 놓고 개발 패널 또는 채팅의 app.close에서 해당 창 선택 후 최종 승인.
3. 선택한 창이 앞으로 나타나 약 0.4초 후 정상 종료 요청을 받는지 확인. 다른 창은 유지되어야 함.
4. 저장 확인창이 표시되면 취소하고 문서가 유지되는지 확인. 앱의 자동 저장·세션 복원 설정에 따라 확인창이 나오지 않을 수도 있음.
5. 표시 중 다른 창으로 전환하거나 대상 창을 닫으면 ACE가 추가 종료를 요청하지 않는지 확인.

자동 테스트는 처리 순서·400ms 대기·포커스 실패/상실 시 종료 차단·대상 변경 시 종료 차단을 확인함. 실제 Windows foreground 정책과 메모장 저장 확인창의 시각적 동작은 별도 수동 검증 대상임.
