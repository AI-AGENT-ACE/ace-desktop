# 검색·복사·채팅 편의 및 음성 거절 보완

2026-10-23 로컬 변경. 커밋·푸시·배포 없음. 사용자 요청에 따라 직전 추가한 백엔드의 문장 기반 AI 우회 라우팅과 고정 답변 처리는 철회. 이전 승인·DB·파일 작업 구현은 보존.

## 변경 범위

- file.search/folder.search: 위치를 생략하거나 directory=drive_c면 이름으로 C 드라이브 탐색. 파일 내용은 읽지 않음. 사용자 경로 우선, 시스템·빌드/패키지 디렉터리는 뒤로 미루되 검색 대상에서 제거하지 않음. 접근 불가·재분석/연결 경로는 건너뜀. 최대 20초/100만 항목으로 제한하고 부분 검색 및 접근 불가 안내 표시. 모든 파일이 빠짐없이 검색된다는 보장은 아님. 최대 결과 50개. 백그라운드 작업에서 실행.
- 검색 범위와 실행/변경 권한은 분리. 기존 허용 사용자 폴더 밖 결과는 경로 표시만 가능하며 해당 Resource ID의 실행을 Rust에서 거부. 경로 재검증·만료 검증 유지. drive_c를 삭제/이동 목적지 권한으로 추가하지 않음.
- 개발 패널 검색: 폴더 입력 없이 찾을 파일·폴더 이름만 입력. 실사용 채팅 역시 AI가 올바른 search 호출을 반환해야 하며 임의 문장을 백엔드에서 가로채지 않음.
- file.copy: 대상 생략 시 원본과 같은 폴더에 '원본의 복사본.txt', 중복 시 '원본의 복사본 (2).txt' 생성. 확장자 유지. 최종 대상은 Rust 승인 설명·스냅샷·실행에 동일하게 적용. 승인 중 파일 상태/최종 이름이 바뀌면 기존 승인은 실패. move의 목적지 필수 조건 유지.
- 개발 패널 복사는 기본적으로 사본 생성, '대상 이름 직접 지정'을 켜면 기존 복사/덮어쓰기 시험 가능.
- 빈 채팅 입력에서 ↑로 현재 대화의 이전 사용자 명령, ↓로 다음 명령/빈 입력. 불러온 문장을 편집하면 기록 탐색 종료. 필요 시 이전 메시지 페이지 로딩. 다른 대화 기록과 섞지 않음.
- 사용자 전송 직후 하단으로 이동. 이전 메시지를 읽기 위해 스크롤한 상태도 전송 시 하단 복귀. 메시지 DB는 변경하지 않음.
- 실행 오류 안내는 X 또는 5초 후 닫힘. 타이머가 더 최근 안내를 지우지 않도록 상태 일치 확인.
- 음소거 실제 결과 mute boolean을 비민감 결과 요약으로 전달하고 Orb 완료 문구에 반영. 원문 명령 해석은 AI 담당 범위로 유지, mute:false를 toggle로 바꾸지 않음.
- 거절 문장부호·정중한 표현·반복 거절·'2번이요' 처리 보강. 불명확한 말은 승인하지 않음. 선택 인식 실패 3회 또는 5초 무응답이면 기존 취소 IPC 사용. 개발 로그는 요청 ID·인식 유무·선택 판정만 기록하며 음성 원문 제외.

## 근거 구분

- 사용자 수동 통과: 최신 O 및 기존 통과 기록 유지. Native 정상/채팅 실패로 명시한 클립보드 읽기·이동·삭제는 각각 구분. 이번 수정 전체에 대한 사용자 재검증은 아직 없음.
- CLI 실제 Windows 파일 시스템: 깊이 7단계 테스트 파일 이름 검색, 제품 파일 작업 함수로 사본 생성 및 원본/사본 내용 일치, 중복 사본 이름 및 목적지 없는 move 거부 통과. 별도 C 드라이브 이름 검색은 임의 이름의 격리 테스트 파일만 검증해 통과. 초기 일반 탐색 순서는 제한 시간 내 파일 미발견으로 실패했고 순서 개선 후 통과. C 드라이브 전체 완전 탐색이나 앱→DB 종단 통과로 확대하지 않음.
- 모의·단위: 카탈로그 검색/복사/경로 제한 관련 5개 통과. Orb 승인·취소 관련 13개(모의 PCM/STT/IPC, 전사 오류/불명확한 말 3회 취소 포함) 통과. Chrome 실제 React 컴포넌트에서 입력 기록·이전 페이지 연결·편집 유지·전송 후 하단 이동 통과(가상 대화 데이터). 실제 마이크 시험 아님.
- 백엔드 빌드·TypeScript·데스크톱 운영 번들 및 개발 패널 제외 검사, cargo check 통과. 기존 큰 번들 경고 유지. 실행 오류 안내 5초 타이머는 코드/타입 검사 범위이며 실제 앱 화면에서 별도 자동 검증하지 않음.
- 미검증: 실제 발화 '취소'의 반복 인식 문제. 사용자는 '인식/확인하지 못했다' 안내였던 것으로 기억한다고 답변. 당시 전사 결과가 없고 정확한 안내도 미확정이므로 STT/문구 매칭 중 어느 단계인지 확정하지 않음. 앞선 자동 성공으로 실기기 거절 성공을 대체하지 않음.
- 미검증: 설치 앱·운영 배포, 모든 C 드라이브 파일 발견, 모든 파일 시스템, 음소거 해제의 실제 AI JSON/Windows 상태 일치. 처리 중(이미 실행 시작 후) 음성 취소는 승인 대기 거절과 다르며 실행된 OS 작업을 되돌린다고 보장하지 않음.

## 이번 변경만 재시험

- 로컬 백엔드 npm run start:dev, 데스크톱 npm run tauri dev로 변경 반영. 설치 앱은 바뀌지 않음.
- 검색: 본인이 만든 테스트 하위 폴더에 고유 이름 파일을 놓음 → Native 패널 '파일 찾기'에 파일명만 입력 → 표시된 실제 위치 확인. 채팅은 '고유이름.txt 찾아줘'로 별도 확인. AI 도구 호출 오류와 검색 결과 없음은 구분.
- 복사: ACE-Native-Test 폴더에 a.txt 준비 → 패널 파일 복사, 원본 a.txt 입력·대상 직접 지정 끔 → 승인창의 a의 복사본.txt 확인 후 복사 → 원본과 사본 존재·내용 일치. 한 번 더 요청하면 (2) 사본 생성.
- 채팅: 현재 방에서 빈 입력 → ↑ 두 번·↓ 두 번 → 순서 확인. 불러온 내용 수정 후 ↑가 작성 내용을 덮어쓰지 않는지 확인. 오래된 대화는 이전 페이지 로딩 후 이어지는지 확인.
- 스크롤: 대화를 위로 올림 → 새 메시지 전송 → 방금 보낸 말풍선까지 하단 이동.
- 오류: 존재하지 않는 테스트 앱 요청 등으로 실행 오류 발생 → X 없이 5초 후 사라짐. 새 오류가 나타나면 새 오류 기준으로 5초 유지.
- 거절: 테스트 메모장만 대상으로 음성 '메모장 닫아줘' → '취소'. 새 요청에서 '아니오', '2번' 각각 시험. 취소 후 창 유지. 계속 인식 실패면 '네'로 진행하지 말고 화면 취소. 인식 실패 3회/무응답 때도 실행되지 않아야 함.
- 음소거: 사용자 필요 시 '음소거 해줘'/'음소거 해제해줘' 각각 요청하고 Windows 표시와 안내 비교. AI가 잘못된 도구/boolean을 내면 AI 계약 문제로 기록; 백엔드가 문장을 임의 재해석하지 않음.

이번 사용자 요청의 O와 빈칸 항목은 재시험 목록에서 제외. 공용 모델·음성 실기기 전체·운영 DB·설치 업데이트 대기 및 객체 저장소/코드 서명 보류 유지.
