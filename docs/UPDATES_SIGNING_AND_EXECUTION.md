# 업데이트·서명·Native 실행 추적 (2026-10-14)

## 구현 범위와 완료 조건

- 설정의 `업데이트 확인` → 새 버전·변경 내용 확인 → 다운로드 진행률 → 서명 검증 → 작업 종료 후 설치 흐름 추가.
- Rust의 공유 작업 잠금으로 녹음·마이크 테스트·캡처·파일 저장·Native 실행 중 설치를 대기함. 설치 시작 후 새 작업 진입 차단. Orb의 승인·음성 처리 중에도 대기함.
- Tauri updater의 다운로드 서명 검증에 성공한 바이트만 설치함. 다운로드·검증 실패 시 설치를 호출하지 않고 기존 앱 유지.
- Windows NSIS 설치 시작 시 앱이 종료될 수 있음. 설치 프로그램 실행 이후 전원 중단 등까지 자동 복구를 보장하는 기능은 아님.
- 사용자 설정·개인 Wake Word 모델의 데이터 경로를 변경하거나 삭제하지 않음. 실제 업데이트 전후 보존 시험은 미실행.
- 승인 화면 전에 Rust에 변경 불가능한 명령·인자·대상 상태를 보관. 승인 시 120초 기한 내 일회성 ID 발급. 실제 실행 시 창·작업·실행 ID·시도 ID·인자·대상을 다시 검사하고 ID를 원자적으로 소비함.
- 승인창에 파일의 원본·대상 또는 선택한 창 제목을 표시. 전체 경로는 로컬 확인 화면에서만 사용하며 실행 추적 로그에 저장하지 않음.
- Windows Authenticode 코드 서명은 **미적용·후속 작업**. 자체 서명 인증서를 대체물로 넣지 않음.

## 사용자가 준비할 Tauri 업데이트 키

실제 개인키·공개키는 생성하거나 등록하지 않았음. 다음 작업은 사용자가 안전한 로컬 환경에서 수행해야 함.

1. 저장소 밖의 안전한 폴더를 만들고, `ace-desktop`에서 아래 명령 실행. 암호는 대화형으로 입력하며 개인키 파일과 암호를 별도로 백업.

   ```powershell
   npx tauri signer generate -w "$env:USERPROFILE\.tauri\ace-update.key"
   ```

2. GitHub 저장소 Settings → Secrets and variables → Actions에 등록.
   - Variable `ACE_UPDATER_PUBLIC_KEY`: 생성된 `.pub` 파일의 내용. 앱에 포함되는 공개 정보.
   - Secret `TAURI_SIGNING_PRIVATE_KEY`: 개인키 파일의 내용. 저장소 파일이나 `.env`에 넣지 않음.
   - Secret `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`: 키 생성 시 지정한 암호.
   - 기존 Variable `PRODUCTION_API_URL` 유지.
3. 공개키를 바꾸면 이전 앱이 새 키의 업데이트를 검증할 수 없음. 키 분실·회전은 별도 배포 계획 필요.
4. 승인된 공용 Wake Word 모델과 검증 기록 공급. 모델 검사 조건을 유지했으므로 모델이 없거나 부적합하면 Release 실패. 개인 모델을 대신 배포하지 않음.
5. `package.json`, `src-tauri/tauri.conf.json`, Cargo 패키지 버전과 태그를 맞추고 `docs/RELEASE_NOTES.md` 작성.
6. Release 워크플로가 NSIS `.exe`, Tauri `.exe.sig`, `latest.json`을 생성해 **초안 Release**에 첨부. 검토·실기기 시험 후 사용자가 정식 Release로 게시해야 앱이 확인 가능.

업데이트 주소는 `https://github.com/AI-AGENT-ACE/ace-desktop/releases/latest/download/latest.json`.
현재 배포된 v0.1.2에 업데이트 기능이 없다면 첫 지원 버전은 설치 파일로 한 번 직접 설치해야 함. 그 버전부터 후속 업데이트 확인 가능.
이번 작업에서는 버전 증가·태그 생성·Release 게시·CI 비밀값 등록을 하지 않음.

## 실행 ID와 백엔드 배포 순서

- `requestId`: 상위 요청. 여러 도구 호출을 같은 요청으로 묶음.
- `executionId`: Native 작업 한 개. 서버 발급 티켓, Rust 승인, Rust 결과, DB 실행 이력에 동일 ID 사용.
- `attemptId`: 대상 재선택·덮어쓰기 등 개별 시도. 재시도는 새 ID와 `previousAttemptId`로 연결.
- `POST /agent/executions`: 음성·설정 등 채팅 외 로컬 작업도 계약과 사용자 권한 검사 후 티켓 발급.
- `POST /agent/executions/events`: REQUESTED / WAITING_APPROVAL / APPROVED / RUNNING / SUCCEEDED / FAILED / DENIED / CANCELLED / EXPIRED 기록.
- `GET /agent/executions/:id`: 로그인한 소유자만 해당 작업의 이력 조회 가능. 만료된 미완료 작업은 조회 시 EXPIRED로 반영.
- 이벤트에는 ID·상태·시각만 저장. 음성 원문·클립보드 내용·전체 파일 경로·승인 토큰은 저장하지 않음.
- 종료된 결과의 덮어쓰기, 다른 사용자의 티켓, 잘못된 재시도 연결과 승인 대기를 건너뛴 실행 상태를 거부. 동일 이벤트 재전송은 중복 저장하지 않음.
- 서버 이력은 인증된 데스크톱의 보고임. Windows 작업을 서버가 독립적으로 증명하는 원격 attestation은 아님.
- 기존 클라이언트의 `attemptId` 없는 결과는 호환 처리. 새 클라이언트 결과는 해당 작업의 시도·최종 상태와 대조함.
- 추가 migration `202610130003_native_execution_trace` 필요. 앞선 로컬 migration도 함께 검토 후 서버에 `prisma migrate deploy` 적용해야 함. 이번 작업에서 DB migration을 적용하지 않음.
- 새 API가 없는 이전 Render 서버에 최신 데스크톱만 연결하면 실행 이력 요청이 실패함. **백엔드 migration·배포 확인 후 데스크톱 배포** 순서 필요.

## 검증과 미실행 항목

자동 검증은 단위 테스트·모의 API/IPC 브라우저 테스트임. 실제 음성·Windows 설치 업데이트 완료로 간주하지 않음.

2026-10-14 확인 결과:

- 데스크톱 프로덕션 웹 빌드 성공. 번들 크기 경고는 남아 있음.
- 백엔드 빌드 및 TypeScript 검사 성공. 전체 단위 테스트 125개 통과 후 실행 추적 테스트 3개 추가·통과.
- Rust 단위 테스트 83개 통과, 실기기 등 11개 미실행. Clippy 경고 없음.
- 기존 브라우저 시나리오 15개 통과. 업데이트 UI 시나리오 추가 후 관련 5개 재검증 통과.
- 음성 흐름 모의 회귀 테스트 6개 통과. 실제 마이크로 녹음한 시험이 아님.
- 기본 브라우저 통합 설정은 로컬 DB 인증 실패로 시작하지 못함. 이후 DB를 사용하지 않는 `playwright.input.config.ts`로 UI 검증. DB 통합 검증은 대기.
- 서명 설정 누락 검사 프로세스는 샌드박스의 자식 프로세스 실행 문제로 완료하지 못함. 실제 키를 사용하는 Release 실행 역시 대기.

- 자동: 승인 후 대상/인자 변경, 다른 호출 창·시도, 만료·재사용 거부, 작업 중 업데이트 설치 차단.
- 자동: 실행 이력 소유권, 상태 전환·중복 이벤트·재시도 연결, 업데이트 버전·진행률·대기·실패 UI.
- 수동 대기: 승인된 공용 모델 준비, 여러 사람 호출·오탐 시험, 개발 폴더 없는 새 PC 설치.
- 수동 대기: 업데이트 지원 버전 A 설치 → 설정·개인 모델 보관 → 버전 B 게시 → 설정에서 확인·다운로드 → 녹음/파일 작업 완료 후 설치 → 버전·설정·개인 모델 유지 확인.
- 수동 대기: 격리된 테스트 배포에서 설치 파일을 변조하고 기존 서명을 유지했을 때 설치 거부·기존 버전 유지 확인. 운영 Release 파일은 변조하지 않음.
- 수동 대기: 실제 다중 모니터·USB 마이크 해제·창 저장 확인·재시작 정리·DB migration 적용 및 이력 조회.
- Windows 코드 서명 유효성·게시자 확인은 서비스 도입 이후 검증.
